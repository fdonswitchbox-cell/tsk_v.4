# Архитектура формирования ответа ИИ

## 1. Процесс (как интегрировать в текущую систему)

Текущий pipeline заканчивается на этапе «приоритеты действий». Добавляется **6 новых этапов** между `compute_priorities()` и возвратом ответа пользователю:

```
Запрос пользователя / Новая заметка
    ↓
--- текущий pipeline до этапа приоритетов ---
    ↓
[НОВЫЙ] Intent Analyzer         ← LLM: тип запроса (аналитика / поиск / причина)
    ↓
[НОВЫЙ] Planner                 ← Python: какие источники нужны
    ↓
[НОВЫЙ] Evidence Builder        ← Python: сбор + приоритизация (тема из Planner — фокус, а не фильтр; кросс-доменные связи сохраняются)
    ↓
[НОВЫЙ] Insight Engine          ← Python: структурированные инсайты
    ↓
[НОВЫЙ] Insight Ranker          ← Python: топ-N инсайтов (уменьшение контекста)
    ↓
[НОВЫЙ] Response Planner        ← LLM: JSON-схема ответа
    ↓
[НОВЫЙ] Response Generator      ← LLM: финальный текст по схеме
    ↓
Ответ пользователю
```

### Бесшовная интеграция

Ничего из существующего не ломается. Новый модуль `answer_engine.py` принимает:

```python
answer_engine.answer(
    user_query="Почему я ничего не успеваю?",
    top_actions=[...],
    entity_stats=[...],
    relations_graph=[...],
    observations=[...],
)
```

Возвращает структурированный ответ с доказательствами.

### Роли компонентов

| Компонент | Технология | Задача |
|-----------|-----------|--------|
| Intent Analyzer | LLM (промпт) | Определить тип запроса: аналитика, поиск, причина, рекомендация |
| Planner | Python | Решить, какие источники нужны (SQL, граф, вектор, все вместе) + указать тему для фильтрации |
| Retriever | Python + SQL | Собрать сырые данные из БД |
| Evidence Builder | Python | Склеить данные в единый контекст, **приоритизировать по теме из Planner, но сохранить все кросс-доменные связи** |
| Insight Engine | Python | Посчитать тренды, корреляции, топ-причины, повторения. **Возвращает структурированные инсайты** |
| Insight Ranker | Python | **Отобрать топ-N инсайтов** (confidence + relevance), сократить контекст для LLM |
| Response Planner | LLM (промпт) | **Вернуть JSON-схему** ответа: `{answer_type, sections: [...]}` |
| Response Generator | LLM (промпт) | Написать финальный текст на русском по JSON-схеме |

## 3. Чек-лист (разбивка на задачи)

### 3.1. Backend — Python (детерминированная логика)

- [ ] Создать `v3-api/app/answer_engine.py` — главный модуль ответов
- [ ] **Intent Analyzer**: 3–5 промптов для классификации запроса (аналитика/поиск/причина/рекомендация/общий)
- [ ] **Planner**: маппинг тип запроса → источники данных (SQL/граф/вектор)
- [ ] **Evidence Builder**: функция `collect_evidence(query_type, focus_topic, ...)` → возвращает словарь с фактами, **приоритизированными по фокус-теме, но с сохранением кросс-доменных связей** (не фильтр, а ранжирование)
- [ ] **Insight Engine — структура**: возвращает массив `insights` с полями `type`, `entity`, `confidence`, `evidence`
- [ ] **Insight Engine — тренды**: `compute_trends(entity_stats, lookback=30d)` → insight типа `trend`
- [ ] **Insight Engine — корреляции**: простая ковариация упоминаний пар сущностей (из `relation_stats`) → insight типа `correlation`
- [ ] **Insight Engine — повторения**: поиск одинаковых наблюдений/действий по временным окнам → insight типа `recurrence`
- [ ] **Insight Engine — корневые причины**: взвешенный рейтинг на основе entity_stats.importance + frequency + trend → insight типа `root_cause`
- [ ] **Insight Engine — выгодные действия**: actions, которые влияют на >1 проблемы (через `action_entities`) → insight типа `leverage_action`
- [ ] **Insight Ranker**: сортировка по `confidence`, отбор топ-5
- [ ] Добавить новый эндпоинт `POST /v3/ask` — принимает вопрос, возвращает ответ

### 3.2. LLM-слой (промпты)

- [ ] Промпт **Intent Analyzer**: «Определи тип вопроса: analytical / causal / search / recommendation / general»
- [ ] Промпт **Response Planner**: «Верни JSON: `{answer_type, sections: ["summary", "evidence", "recommendation"]}»
- [ ] Промпт **Response Generator**: сценарии:
  - Для аналитики: статистика + тренды
  - Для причины: Evidence + корреляции + вывод
  - Для рекомендации: топ-действий + ожидаемый эффект
  - Для поиска: векторный контекст + ответ

## 4. Что решит это

### 4.1. Текущие проблемы которые решаются

| Проблема | Сейчас | После внедрения |
|----------|--------|----------------|
| Ответ не связан с вопросом | Возвращаются сырые топ-действия | LLM интерпретирует данные под вопрос |
| Нет анализа причин | Только веса, без объяснения | Insight Engine находит корреляции |
| Нет контекста | Пользователь видит число 1050 | Пользователь видит «главная причина — сон, подтверждено 12 раз» |
| Нет доказательств | Только приоритет | Evidence Builder показывает «вот какие заметки подтверждают» |
| Один источник для всех запросов | Всегда один и тот же pipeline | Intent → разные источники |

### 4.2. Что система научится делать

- **Отвечать на «почему»**: «Потому что недосып влияет на продуктивность (корреляция 0.82)»
- **Давать персонализированные рекомендации**: «Улучшив сон, ты повлияешь на работу, стресс и продуктивность»
- **Показывать динамику**: «За последние 2 недели качество сна упало на 30%»
- **Находить повторяющиеся паттерны**: «Ты 5 раз писал одно и то же — это системная проблема»
- **Разделять типы запросов**: аналитика ≠ поиск ≠ причина

## 5. Пример (полный цикл)

**Запрос пользователя:** «Почему я ничего не успеваю на работе?»

### Шаг 1. Intent Analyzer (LLM)
```
Тип: causal
Причина: пользователь хочет понять связь между действиями и результатом
Источники: SQL + граф
```

### Шаг 2. Planner (Python)
```
Нужны:
- entity_stats (importance, trend)
- actions (priority_score)
- relations (связи между проблемами)
- observations (заметки за последние 30 дней)
```

### Шаг 3. Retriever + Evidence Builder (Python)
```json
{
  "entities": [
    {"name": "сон", "importance": 142, "trend": -0.3, "mentions": 18},
    {"name": "прокрастинация", "importance": 85, "trend": +0.2, "mentions": 16},
    {"name": "работа", "importance": 105, "trend": -0.1, "mentions": 22}
  ],
  "relations": [
    {"from": "недосып", "to": "прокрастинация", "strength": 0.82}
  ],
  "observations": [
    {"text": "Если плохо сплю — ничего не делаю", "date": "2026-05-14"},
    {"text": "Опять завалил дедлайн из-за усталости", "date": "2026-06-02"}
  ],
  "top_actions": [
    {"action": "Настроить режим сна", "score": 1050},
    {"action": "Изучить техники тайм-менеджмента", "score": 720}
  ]
}
```

### Шаг 4. Insight Engine (Python)
```json
{
  "insights": [
    {
      "type": "root_cause",
      "entity": "Недосып",
      "confidence": 0.91,
```

### Шаг 4.5. Insight Ranker (Python)
```json
{
  "ranked_insights": [
    { "type": "root_cause",     "entity": "Недосып",         "confidence": 0.91 },
    { "type": "leverage_action", "action": "Настроить сон",   "confidence": 0.88 },
    { "type": "correlation",    "from": "Недосып", "to": "Прокрастинация", "confidence": 0.85 },

// Отобрано 4 инсайта из 12 найденных (отсев по confidence < 0.5)
```

### Шаг 5. Response Planner (LLM)
```json
{
  "answer_type": "causal",
  "sections": ["summary", "evidence", "recommendation"]
}
```

### Шаг 6. Response Generator (LLM)

> **Главная причина — недостаток сна.**
>
> За последние 3 месяца эта проблема упоминалась 18 раз, и её влияние на продуктивность растёт.
>
> **Почему это важно:**
> - Между недосыпом и прокрастинацией обнаружена сильная связь (0.82 из 1.0)
> - 6 раз прослеживается цепочка: «не спал → не сделал → стресс»
> - За последнюю неделю качество сна упало ещё на 10%
>
> **Что делать:**
> 1. Настроить режим сна (ложиться до 23:00) — это решит не только сон, но и продуктивность на работе
> 2. Убрать сладкое на ночь — улучшит качество сна на 20–30%
> 3. Внедрить вечерний ритуал (без экранов за 1 час до сна)
>
> *Подтверждено заметками от 14 мая, 2 июня и 18 июня 2026.*

### Ключевой принцип

**Python делает то, что можно точно вычислить.** LLM делает то, что требует интерпретации.

Python: тренды, частоты, корреляции, топ-N, агрегаты, фильтры.
LLM: почему это важно, что из этого следует, как объяснить человеку.

Разделение позволяет:
- Менять LLM без переписывания аналитики
- Делать аналитику быстрой (Python) и дешёвой
- Использовать LLM только там, где она реально нужна
- Всегда иметь объяснение для любого вывода (прозрачность)
