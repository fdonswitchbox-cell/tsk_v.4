# Аудит архитектуры проекта

Ты выступаешь в роли Senior Software Architect, Data Engineer и AI Architect.

Твоя задача — провести полный аудит проекта и проверить не качество кода, а правильность архитектуры, логики обработки данных и аналитических процессов.

Не соглашайся с текущей реализацией автоматически. Ищи слабые места, лишние этапы, нарушения логики, потенциальные проблемы масштабирования и ошибки проектирования.

---

## Что необходимо проверить

### 1. Полный pipeline обработки данных

Проследи путь данных от момента создания пользователем заметки до получения аналитики.

Для каждого этапа ответь:

* что получает на вход
* что делает
* что возвращает
* какие данные теряются
* какие данные создаются
* есть ли дублирование
* можно ли убрать этап
* можно ли объединить несколько этапов

Нарисуй цепочку обработки в виде схемы.

---

### 2. Разделение ответственности

Проверь, правильно ли распределены обязанности между:

* Python
* LLM
* PostgreSQL
* Graph Builder
* LightRAG (если используется)
* Векторной базой
* Knowledge Graph

Для каждого компонента ответь:

* действительно ли он должен выполнять именно эти функции
* не делает ли он чужую работу
* чего ему не хватает
* есть ли лишняя логика

---

### 3. Извлечение данных

Проверь, правильно ли организовано извлечение информации из заметок.

Особенно оцени:

* сущности
* наблюдения
* проблемы
* решения
* действия
* события
* привычки
* эмоции
* цели
* проекты
* связи между объектами

Ответь:

* кто именно должен извлекать каждый тип данных
* Python или LLM
* достаточно ли текущей схемы
* где возможны ошибки

---

### 4. Аналитика

Это главный раздел.

Проверь, сможет ли текущая архитектура строить качественную аналитику без полной переработки.

Особенно оцени возможность автоматически находить:

* повторяющиеся проблемы
* причины проблем
* последствия
* закономерности
* триггеры
* успешные решения
* неудачные решения
* корреляции между сущностями
* влияние одной проблемы на другую
* влияние действий на результат
* эффективность решений
* изменение состояния пользователя во времени

Также оцени возможность вычислять:

* самые важные проблемы
* самые дорогие проблемы
* наиболее эффективные действия
* приоритет задач
* ключевые точки роста
* главные источники стресса
* самые полезные привычки

Если какая-либо аналитика невозможна — объясни почему.

---

### 5. Приоритизация

Проверь, сможет ли система автоматически определить:

какую проблему нужно решать первой.

Например:

Проблема А блокирует решение пяти других проблем.

или

Одно действие автоматически решает несколько задач.

Проверь, достаточно ли текущих данных для такой аналитики.

Если нет — укажи, чего не хватает.

---

### 6. Связи

Проверь качество модели связей.

Какие отношения должны существовать между объектами:

Problem → Cause

Problem → Solution

Solution → Action

Action → Result

Person → Habit

Habit → Emotion

Goal → Project

Observation → Problem

Problem → Emotion

Action → Habit

Solution → Effect

и другие.

Предложи недостающие связи.

---

### 7. Graph Builder

Если используется Graph Builder, оцени:

* действительно ли он нужен
* должен ли он работать поверх LightRAG
* какие данные он получает
* какие создаёт
* какие связи должен строить
* не дублирует ли работу LLM
* не дублирует ли работу Python

---

### 8. PostgreSQL

Проверь модель хранения.

Оцени:

* нормализацию
* связи
* индексы
* масштабируемость
* возможность выполнять сложную аналитику SQL-запросами

---

### 9. Масштабирование

Представь, что база содержит:

* 100 000 заметок
* 5 миллионов сущностей
* 50 миллионов связей

Определи:

* какие узкие места появятся
* что станет работать медленно
* какие части архитектуры потребуют переработки

---

### 10. Финальное заключение

Составь итоговый отчёт в виде таблицы.

| Компонент | Оценка (1–10) | Проблемы | Что исправить |
| --------- | ------------- | -------- | ------------- |

После таблицы перечисли:

* критические ошибки
* потенциальные проблемы в будущем
* лишние компоненты
* недостающие компоненты
* рекомендации по упрощению архитектуры
* рекомендации по улучшению аналитики
* рекомендации по улучшению качества извлечения данных
* рекомендации по масштабированию

Не ограничивайся поиском ошибок. Предлагай более удачные архитектурные решения, если они существуют, и объясняй, почему они лучше.
